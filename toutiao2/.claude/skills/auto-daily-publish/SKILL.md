# 自动化头条发布工作流

端到端自动化：检测已有文章 → (无则)自动生成Top3热点文章 → 取最旧一篇发布到头条号 → 删除已发布文章。下次触发时继续处理剩余文章。

> **配置说明**：`{output_dir}` 表示文章输出目录，从 `config/platforms.yaml` 的 `output_dir` 字段读取。

## 前置依赖

- **brain skill**：记忆系统，用于加载历史发布记录、去重过滤候选话题、记录新发布
- **daily-hot-article skill**：用于生成热点文章
- **toutiao-publisher skill**：用于发布文章到头条号
- Chrome DevTools MCP：toutiao-publisher 的底层依赖
- 用户已在浏览器中登录头条号

## 工作流程

```
┌─────────────────────────────────────────────┐
│  Phase 1: 扫描文章                             │
│  扫描 {output_dir}/ 下是否有 *_头条文章.md        │
├─────────────────────────────────────────────┤
│  有文章 ──→ Phase 3 (跳过生成)                  │
│  无文章 ──→ Phase 2 (生成文章)                  │
├─────────────────────────────────────────────┤
│  Phase 2: 生成文章                             │
│  调用 daily-hot-article，自动选取 Top 3 热点     │
│  批量生成 3 篇 .md 头条文章                      │
├─────────────────────────────────────────────┤
│  Phase 3: 发布一篇                             │
│  取最旧一篇 *_头条文章.md，调用 toutiao-publisher │
├─────────────────────────────────────────────┤
│  Phase 4: 清理                                │
│  发布成功后删除该 .md 文件，流程结束             │
└─────────────────────────────────────────────┘
```

---

## Phase 1：扫描现有文章

扫描 `{output_dir}/` 目录，查找所有 `*_头条文章.md` 文件：

- **排除规则**：排除目录下的 SKILL.md、README.md 等非文章文件，只匹配以 `_头条文章.md` 结尾的文件
- **有文章 → 跳过生成**：直接进入 Phase 3 发布流程
- **无文章 → 进入 Phase 2**：自动生成热点文章

---

## Phase 2：自动生成 Top 3 热点文章

当 `{output_dir}/` 下没有现有文章时，调用 `daily-hot-article` skill 自动生成 3 篇热点文章。

### 2.1 搜集热点（daily-hot-article Step 1-2）

按 `daily-hot-article` skill 的 Step 1 和 Step 2 执行：

1. 运行 `python ./scripts/fetch_and_analyze.py`（路径相对于 daily-hot-article skill 目录，即 `.qoder/skills/daily-hot-article/scripts/fetch_and_analyze.py`）
2. AI 二次审视 + 五维评分，提炼 Top 5 热点

### 2.2 自动选取 Top 3（跳过 Step 3 用户确认，经 brain 去重）

**重要：此步骤跳过用户交互，自动决策，且经 brain 记忆系统去重。**

1. **加载 brain 记忆**：使用 `Skill: brain` 调用 `load()` 操作，从 Obsidian 加载历史发布记录到内存
2. 从 Top 5 中取**热度最高的前 5 个**作为候选话题
3. **调用 brain 去重**：使用 `Skill: brain` 调用 `filter(candidates=候选列表)` 操作，过滤掉已发布过的话题
4. 从过滤后的未发布话题中取**前 3 个**
5. 如果过滤后不足 3 个，告知用户可用话题不足，有剩则全部生成
6. 无需用户确认，直接进入写作

### 2.3 批量生成 3 篇文章（daily-hot-article Step 4-8）

对每个选中的话题，依次执行 daily-hot-article 的 Step 4-8：

| 步骤 | 内容 | 操作 |
|------|------|------|
| 4 | 素材深度调研 | 纵向脉络 + 横向切片 + 文章骨架 |
| 5 | 生成头条文章 | 犀利尖锐风格，约 800 字，写入 `.md` 文件 |
| 6 | 搜索并插入配图 | 新闻原图优先，2-3 张 |
| 7 | 验证配图完整性 | `python ./scripts/verify_md_images.py` |
| 8 | 输出结果 | 确认文件生成完毕 |

**循环执行**：第 1 个话题 → 完成 → 第 2 个话题 → 完成 → 第 3 个话题 → 完成。

所有文章输出到 `{output_dir}/`，文件名格式：`{话题标题}_头条文章.md`。

### 2.4 写作规范

与 daily-hot-article 完全一致：
- 标题不超过 28 字，有锋芒
- 约 800 字，极限不超过 1000 字
- 配图 2-3 张，分辨率不低于 800x600
- 零失效图片

---

## Phase 3：发布最旧一篇文章

从 `{output_dir}/` 下所有 `*_头条文章.md` 中，**取修改时间最旧的一篇**进行发布。只发布一篇，不循环。

### 3.1 发布单篇文章

调用 `toutiao-publisher` skill，完整执行其发布流程（Step 1-10）：

1. 加载 chrome-devtools MCP 工具
2. 导航到 `https://mp.toutiao.com/profile_v4/graphic/publish?from=toutiao_pc`
3. 扫描文章（取当前最旧的未发布文章）
4. 解析 Markdown 内容（标题、正文、图片）
5. 定位页面元素
6. 填写标题（click + type_text）
7. 上传本地图片（如有）
8. 填写正文（ClipboardEvent 粘贴方式）
9. 点击预览并发布（处理封面图问题）
10. 验证发布结果（检查"提交成功"）

### 3.2 发布结果判断

- **成功**：`take_snapshot` 中出现 `StaticText "提交成功"` → 进入 Phase 4 清理
- **失败**：记录失败原因，告知用户，流程结束

---

## Phase 4：清理已发布文章

发布成功后，执行以下操作：

1. **记录到 brain 记忆**：
   - 从已发布文章的 `.md` 文件中提取标题（第一个 `# ` 后的文本）
   - 获取当前日期（YYYY-MM-DD 格式）
   - 使用 `Skill: brain` 调用 `record(title=文章标题, date=当前日期)` 操作，brain 会同时更新内存和写回 Obsidian
2. **删除本地文件**：
   ```
   删除 {output_dir}/{文章文件名}.md
   ```

删除前确认：
- 发布结果已验证为成功
- brain.record() 已成功执行
- 文件路径正确（仅删除 `.md` 文件，不删除配图等资源）

流程到此结束，不处理剩余文章。

流程结束后，向用户汇报：

## 注意事项

- **每次只发一篇**：本技能每次调用只发布最旧的一篇文章，不在单次调用中循环。多篇文章需多次调用
- **Phase 2 跳过用户确认**：Top 3 自动选取，无需等待用户输入
- **Phase 3 取最旧文章**：按修改时间排序取最早的那篇，作为 toutiao-publisher 的输入
- **Phase 4 即删**：发布成功后立即删除对应的 `.md` 文件，避免重复发布
- **中断恢复**：如果发布失败，文件保留在文件夹中，下次触发时从 Phase 3 继续
- **文件编码**：所有 `.md` 文件为 UTF-8 编码
