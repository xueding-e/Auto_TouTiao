# 模式三: 已有用例 → 浏览器预探索 → 标准格式转换

> 本文档为 `test-case-generator` skill 的模式三详细规则,只描述模式三独有的内容。共用部分见: [SKILL.md](../SKILL.md)(整体流程与浏览器探索) | [ai-benchmark-syntax.md](./ai-benchmark-syntax.md)(AI 验证基准语法) | [page-structure-yaml-spec.md](./page-structure-yaml-spec.md)(yaml 规范)

---

## 1. 模式说明与输入特征

- **输入**: 已有用例文件(`.md`/`.txt`/`.xlsx`/`.csv`)/ markdown 文本 / 自然语言描述 / 半结构化表格
- **功能点来源**: 原始用例
- **浏览器探索角色**: 辅助性预探索(仅 navigate+snapshot,不深度交互),用于校准元素名
- **失败后果**: 可降级,用例保留 `<>` 占位符仍能生成

> 浏览器预探索的完整流程见 [SKILL.md](../SKILL.md) 第二步。模式三在转换用例前必须先完成预探索。

---

## 2. 已有用例解析

**解析目标**: 从任意格式的已有用例中提取以下核心信息:
- **功能点描述**: 用例测试的是什么功能
- **操作步骤**: 用例的执行步骤(点击/输入/选择等)
- **预期结果**: 执行后期望的结果
- **优先级/等级**: 原始用例的优先级(若有)
- **关联需求**: 原始用例关联的需求(若有)

**解析规则**:
- 识别"用例编号/标题/前置条件/步骤/预期结果"五段式结构
- 识别表格形式的用例(可能列名不同,需字段映射)
- 识别自然语言描述的用例(提取动作动词和目标元素)
- 步骤中的操作描述提取为"点击步骤"
- 缺失字段用合理默认值填充(等级默认 p1,关联需求点标 `-`)

---

## 3. 字段映射规则

已有用例常见字段 → 标准7列字段映射:

| 已有用例常见字段 | 标准7列字段 | 说明 |
|----------------|-----------|------|
| 优先级/级别/等级 (P0/P1/P2/高/中/低/L1/L2/L3) | 等级 | P0/高/L1 → p0; 其余 → p1 |
| 用例标题/功能点/测试目的 | 功能点描述 | 直接映射,精简为功能点描述 |
| 测试步骤/操作步骤/执行步骤 | 点击步骤 | 合并为步骤文本,格式"1.xxx 2.xxx 3.xxx" |
| 预期结果/期望结果 | 预期结果 | 直接映射,多条用分号分隔 |
| 预期结果/期望结果 | AI验证基准 | 从预期结果推导,转为 snapshot 可观测描述(见第 5 节) |
| 需求编号/关联需求/需求ID | 关联需求点 | 直接映射;无则填 `-` |
| 前置条件 | (合并入点击步骤) | 作为步骤前的说明,用"前置:"前缀 |

---

## 4. 功能点清单与页面结构

> 模式三将原始用例按功能点归类后填入 `features[]`,`cases` 为转换后分配的标准用例编号(`TC-<模块缩写>-<序号>`)。预探索后产出 `page_structure` 页面结构描述,字段规范详见 [page-structure-yaml-spec.md](./page-structure-yaml-spec.md)。

```yaml
module: 功能测试
source_type: convert
url: https://example.com  # 预探索后填入实际URL
generated_at: 2026-06-19T12:00:00+08:00
features:
  - id: FP-001
    name: 登录功能
    source: 原始用例
    cases: [TC-LOG-001, TC-LOG-002]
  - id: FP-002
    name: 搜索功能
    source: 原始用例
    cases: [TC-SCH-001]
```

### 4.1 转换后补全

在转换过程中,根据原始用例内容,适当补全以下场景(若原始用例明显遗漏):
- 原始用例只测正常路径 → 补充一条 p1 级异常/边界用例
- 原始用例有必填字段但未测空值 → 补充空值校验用例
- 补全的用例在"关联需求点"列标注 `(补全)`

> **注意**: 补全场景需有依据(来自原始用例上下文),不臆造。

## 5. AI 验证基准生成(模式三场景映射表)

> 共用语法规则(检查项结构、类型判定、语义匹配、.md ↔ yaml 映射)见 [ai-benchmark-syntax.md](./ai-benchmark-syntax.md)。本节仅列出模式三的"预期结果→基准转换映射"和生成规则。

模式三的 AI验证基准从原始用例的**预期结果**推导,转为 snapshot 可观测描述。预探索获取的真实元素名直接填入,不再使用 `<>` 占位符。

### 5.1 预期结果→基准转换映射

| 原始预期结果(业务语言) | AI验证基准(snapshot 可观测) |
|----------------------|--------------------------|
| 跳转首页 | `【步骤N后】①snapshot中URL已从登录页变为首页地址;②页面存在"<真实首页特征元素>"等界面元素;③页面不再出现登录表单;④页面不出现error提示` |
| 提示"用户名必填" | `【步骤N后】①snapshot中仍存在登录表单(未跳转);②页面出现含"必填"/"不能为空"/"请输入"的校验提示;③URL未变化` |
| 列表显示包含"智能体"的记录 | `【步骤N后】①snapshot中表格/列表刷新;②所有可见行均包含"智能体"关键字;③底部"共N条"中N值≥1` |
| 创建成功 | `【步骤N后】①snapshot中不再出现"<真实对话框标题>"对话框;②列表中出现含"<操作内容>"的新增记录;③列表行数比操作前增加1;④可能出现含"成功"的提示` |
| 删除成功 | `【步骤N后】①snapshot中不再包含被删除的记录;②底部"共N条"中N值比操作前减少1;③可能出现含"成功"/"删除成功"的提示` |
| 对话框关闭;未修改 | `【步骤N后】①snapshot中不再出现"<真实对话框标题>"对话框;②<目标区域>内容与操作前一致;③列表行数无变化` |

### 5.2 生成规则

1. 逐条读取原始用例的"预期结果",判断场景类型,套用对应场景模板
2. 跳转类:描述 URL 变化+目标页面特征+反向断言(无旧页面元素)
3. 提示类:使用 `含"A"/"B"` 格式给出多个近义校验词
4. 数据变化类:必须量化变化量(如"比操作前增加1")
5. 取消/关闭类:必须包含"内容与操作前一致"的对比断言
6. 每条基准以 `【步骤N后】` 开头,多个验证点用 `;` 分隔
7. **预探索后**: 所有 `<>` 占位符必须替换为预探索获取的真实元素名;若预探索降级则保留 `<>` 占位符并标注"待页面探索确认"
8. 补全用例的 AI验证基准同样按上述规则生成,标注方式与关联需求点一致

---

## 6. 输出特点

模式三**先进行浏览器预探索,再转换用例**,因此:
- "点击步骤"列从原始用例的操作步骤转换,并结合预探索获取的真实元素名补全(如"点击'登录'按钮"、"在'用户名'输入框输入"),步骤具体可执行
- "AI验证基准"列从原始用例的预期结果推导 + 预探索真实元素名填充,转为 snapshot 可观测描述,无 `<>` 占位符
- "关联需求点"列从原始用例的需求编号映射,无则填 `-`
- 补全用例标注 `(补全)` 以区分原始用例
- 原始用例的全部场景必须完整转换,不可遗漏
- `.page-structure.yaml` 中 `url` 填入实际 URL,并产出 `page_structure` 页面结构描述
- 若预探索降级,用例中保留 `<>` 占位符并在 `.md` 顶部标注降级原因

---

## 7. 失败处理

| 场景 | 处理 |
|------|------|
| 已有用例解析失败 | 报错并输出原始文本片段,提示修正格式 |
| 原始用例字段缺失 | 用默认值填充(等级 p1,关联需求点 `-`),不阻断转换 |
| 预探索失败(URL 不可访问 / MCP 不可用 / snapshot 为空) | 降级为无探索模式,用例中保留 `<>` 占位符,并在 `.md` 顶部标注 `> ⚠️ 预探索失败: <原因>,用例中 UI 元素名使用占位符,待页面可访问后补全` |
